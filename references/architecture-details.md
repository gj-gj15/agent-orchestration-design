## 1. 分支判定表（第 9-10 步全部出口）

| 分支点 | 判定条件 | 走向 |
|---|---|---|
| 第 9 步 · 通过 | 协查判定验收标准全部满足 | 收回技能与权限（三件事 + 验锁）→ 实例销毁 → 进第 10 步 |
| 第 9 步 · 任务级失败 | 失败归因于子 Agent 执行（幻觉、技能用错、局部疏漏），未命中路线级信号 | 对症换变量重试（换实例 / 换技能包 / 带失败报告重派）→ 回第 6 步；单任务重试 ≤ 2 次 |
| 第 9 步 · 路线级失败 | 命中路线级失效信号：同路线 ≥ 3 个不同任务失败 / 失败原因指向路线隐性假设 / 协查报告连续指向同一路线级问题 | 暂停，带完整现场升级用户 Go/No-Go。Go → 修改路线、重新冻结、继续；No-Go → 项目终止，销毁所有实例 |
| 第 9 步 · 标准问题 | 协查报告"标准太松没法验"或"标准互相冲突" | 打回主 Agent 重审验收标准，重新冻结后重派；不计入子 Agent 重试次数 |
| 第 9 步 · 超限 | 单任务重试或项目总预算触顶 | 带完整现场升级用户，不自动续命 |
| 第 10 步 | 任务队列是否为空 | 非空 → 回第 6 步（新建实例）；空 → 进第 11 步清场 |

关键提醒：**所有分支的终点都含实例处置**。通过、失败、换人、升级用户，每条路径都收回 + 销毁；项目结束时全部销毁，日志库按留存策略归档（供审计与协查统计用），不随项目销毁。

## 2. 螺丝分层归属表

落位判据：提示词管决策，代码管机制；规划层与执行层之间只流冻结的任务图。

| 螺丝 | 数据半截 · 冻结任务图 | 提示词半截 · 主 Agent 系统提示 | 机制半截 · 编排器代码 |
|---|---|---|---|
| 五 · 实例即焚 | 每任务节点标记敏感级别 | — | 实例销毁、撤权三件事、验锁（试调用 + 回执） |
| 六 · 证据带外 | 验收标准写明证据源（带外日志 / 产物） | — | 日志库采集、哈希链、协查直读通道 |
| 七 · 失败举证 | 每任务写死重试上限 + 预算上限 | 只裁报告不裁活；重试对症换变量 | 封顶强制执行；升级现场打包 |
| 八 · 标准冻结 | 标准 + 判定口径（收紧验证槽） | 冻结自检：标准冲突检查 | 协查按标准查的通道；"标准太松/冲突"上报通道 |
| 九 · 漂移过门 | 决策门[] + 路线级失效信号[] | 门禁意识：计划级变更必须过门 | 拦截"偷偷改计划"的门禁逻辑 |
| 仪表 · 协查健康度 | — | — | 误杀/漏放统计、按项目轮换、只读权限 |

反模式：把机制写进提示词——得到的是纸面合规。文档说"已收回"，运行时什么都没发生。每个机制项在代码层必须有对应实现与测试，文档只负责声明义务。

## 3. 九槽位对应表

冻结的任务图 = 子 Agent 的实例化清单（与 intent-to-taskgraph 技能衔接）：

| 槽位 | 执行层对应 | 说明 |
|---|---|---|
| 目标 | 任务完成定义 | 验收的对象 |
| 输入 | 子 Agent 的起点材料 | 任务单的输入清单 |
| 输出 | 交付物格式 | 协查核对交付物的形态 |
| 能力 | 技能选择 | 决定从角色库挑哪个模板 |
| 权限 | 授权清单 | 最小授权范围，撤权依据 |
| 资源 | 预算上限 + 重试上限 | 封顶的数值来源 |
| 验证 | 验收标准 + 判定口径 | 协查按此查，必须指向独立可观察证据 |
| 约束 | 红线 | 含敏感级别标记，决定实例处置 |
| 回退 | 失败分支 + 升级路径 | 第 9 步分支的依据 |

## 4. 任务图契约字段（已实装）

intent-to-taskgraph v0.4.0 已按此契约实装冻结字段，机器版任务图冻结时必须包含：

```yaml
任务图级:
  决策门:
    - {id: DG-1, 位置: 路线级失效信号触发时, 升级对象: 用户,
       选项: [Go: 改路线重新冻结, No-Go: 终止并销毁]}
  路线级失效信号:
    - "同路线上 ≥ 3 个不同任务失败"
    - "失败原因指向路线隐性假设"
    - "协查报告连续指向同一路线级问题"
每任务节点:
  验收: {标准: ..., 判定口径: ..., 证据源: 带外日志 / 产物}
  权限清单: [...]
  预算: {重试上限: 2, 成本上限: ...}
  敏感级别: 普通 | 敏感（实例即焚）
```

注意：本契约已于 2026-10-11 实装为 intent-to-taskgraph v0.4.0。两个技能经此接口对接：本技能的实例化清单以 v0.4.0 冻结契约为准；若两侧 schema 演进，以 intent-to-taskgraph 的冻结契约为接口权威，本表同步跟进。

## 5. 设计决策记录 D1-D7

| # | 决策点 | 选择 | 理由 | 被否掉的备选 |
|---|---|---|---|---|
| D1 | 结果检查归谁 | 独立协查 | 主 Agent 自查有同源盲区 | 主 Agent 自查 |
| D2 | 协查独立性最低档 | 不同模型 | 同模型盲区相同，换提示词不换模型等于一起瞎 | 仅换提示词 |
| D3 | 日志通道 | 带外采集 + 协查直读 | 子自交不可信；主 Agent 中转会成唯一信使 | 子 Agent 交日志 / 主 Agent 转发 |
| D4 | 实例复用 | 每任务新建（v1） | 上下文 append-only + 行为残留，复用是把漏洞请回来 | 复用 + 强制清空 |
| D5 | 重试策略 | 对症换变量 + 封顶 | 同状态重试 = 重抛同一枚硬币；不封顶会烧钱 | 原地同状态重试 |
| D6 | 路线级失效处理 | 用户 Go/No-Go 决策门 | 计划经用户确认才冻结，主 Agent 无权偷偷改道 | 主 Agent 自行改道重派 |
| D7 | 架构规则落位 | 数据进任务图；行为分提示词 / 代码 | 提示词管不了机制；规则要放在会被加载的地方 | 九颗螺丝全部写进 intent-to-taskgraph 技能 |

## 6. 已知限制

- **安全模型是"防失控，不防对抗"**：对抗性注入、绕过校验的恶意命令不在 v1 防护范围内。
- **并行子 Agent 延后**：v1 串行派发。并行编排（含共享状态协调、并发日志写序）推到 v1 之后。
- **主 Agent 仍是编排单点**：任务图与调度本身是主 Agent 的单点产物，靠协查"标准冲突 / 太松"报告与用户决策门兜底。
- **行为残留无法根除**，只能靠实例即焚缓解——这是 LLM 上下文机制决定的。
- **验锁、哈希链、误杀/漏放统计都是代码义务**：守则定义"应该做什么"，实现遗漏时提示词层无法补救。
- **协查轮换的随机性与日志留存策略**依赖运行时实现质量，需在实现阶段专项测试。
- **角色库 schema 未定义**：角色 = 技能包 + 提示词 + 权限基线的组合关系需正式定义。对话平台降级版按能力槽从可用提示词模板临场匹配，不追求跨项目一致性（见任务图执行器降级声明与完全体缺口清单①）。
- **技能注册表与角色库的层级关系未定义**：技能为注册表内独立可复用单元，与角色的组合关系需一并定义。对话平台无持久化注册表，技能即任务卡内的提示词片段，用完即弃、不跨任务复用（对应完全体缺口清单②）。
- **任务节点 ID ↔ 日志 ID ↔ 实例 ID 的关联字段未定义**：随带外日志通道实装时一并补齐（对应完全体缺口清单③）。
